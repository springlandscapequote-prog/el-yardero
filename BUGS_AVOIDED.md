# Bugs of the old El Yardero site and how this app avoids them

Source: Google Doc "El Yardero Site — Changes & Issues" (the old ChatGPT Sites project: a private preview with no public URL).
That log lists **one** open item. The other rows are risks taken from the Brain doc's own rules and from common problems of this kind of site; they are marked so nothing is overstated.

| # | Old bug / risk | Where it came from | How the new app avoids it | Test |
|---|---|---|---|---|
| 1 | **HIGH — Suggested questions only pre-filled the input** (carousel; asked by Fernando and Dan, 2026-10-09) | Bug log | Chips call `ask()` directly on tap: the question is added to the conversation, a typing indicator shows ~0.5 s, then the answer appears. The chip never writes into the input (the input stays empty). The answer is computed on the device (no network), so it cannot hang. Every starter question is also verified at build time to return an answer. | `tests/chips_test.js` (all 8 chips x ES/EN = 16 answers with a source); `tests/e2e.py` taps every chip in both languages on iPhone 13 WebKit and Pixel 7 Chromium (also at 4x CPU slowdown) and checks: an answer with a source link, the invitation text, the input still empty. |
| 2 | Site was a private preview with no public address | Bug log header | Public repo + GitHub Pages: https://springlandscapequote-prog.github.io/el-yardero/ ; hash routes work on refresh and as deep links. | e2e: deep link `#/lesson/speed-sells` after reload; live test on the Pages URL. |
| 3 | Answers must never need a live AI that is not connected ("never simulate live AI with canned replies") | Brain doc, sync section | The Ask screen says plainly it is an AI guide that, for now, searches the lessons and builds a short answer from them; every answer lists its source lessons. A real AI can be added later through `ASK_API_URL` (proxy) with automatic fallback. | e2e: API failing -> local answer; API working -> API answer shown. |
| 4 | Internal inbox / private notes leaking into public content | Brain doc rules | Only the public marker block is parsed; hard safety checks in `tools/sync_brain.py` (marker pair, verbatim-from-block, internal words, dollars/e-mail/URL/phone, unknown capitalised words, shrink guard); `tools/check_data.py` re-checks in CI. Pending (unapproved) lessons are kept outside git. | `tests/sync_safety_test.py` (8 cases). |
| 5 | Answer shown for the wrong language / language lost | typical | Spanish default; ES/EN toggle in localStorage (try/catch); typed English questions are answered in English even in the Spanish UI; the conversation survives a language switch. | e2e: toggle, reload, typed EN question in ES UI. |
| 6 | Double-fire / ghost taps on phones | typical (Safari) | Plain `<button>` / `<form>` `click`/`submit` handlers (no touch+click duplicates); empty input ignored. | e2e: touch taps (`page.tap`), empty submit ignored. |
| 7 | iPhone height / keyboard problems (`100vh`) | typical (Safari) | No fixed-height containers; normal page scroll; `min-height:100vh` + `100dvh`; the input sits at the top of the Ask page under the header so the keyboard never covers it; safe-area insets. | e2e at 390x664 and 375x553. |
| 8 | Horizontal scrolling / text too small | typical | Wrapping everywhere (`overflow-wrap`), 18-19 px lesson text, 48+ px tap targets. | e2e: `scrollWidth <= innerWidth` on home, lesson, ask; font-size checks. |
| 9 | Back button breaks single-page sites | typical | Hash routing (each lesson / Ask is a history entry); list scroll position restored. | e2e: back from lesson to list, from lesson to Ask, after next/previous. |
| 10 | Old version stuck on phones after an update | Happy Colors history | `version.json` auto-update with loop guard, stamped by a GitHub Action on every push (incl. Brain syncs). | e2e: idle -> one reload; typing -> banner only; up to date -> nothing. |
| 11 | Sync freshness could not be verified | Bug log / Brain sync design | Footer shows "Última sincronización / Last synced" and the lesson count from `data/sync.json`. | e2e: footer text. |
